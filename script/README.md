# script/ —— 底座仓里的脚本

这个目录里的脚本**不属于底座本身**，它们是**三个仓共用的开发工具**。它们住
在底座仓，是因为共用它们的东西（审计与脱敏的守卫、委派凭据的门禁）也在底座
这一侧 —— 抄三份，三份就会漂，而漂了的那份是最少有人看的那份。

## 目录里的东西

| 脚本 | 干什么 | 为什么在这儿 |
|---|---|---|
| `mutate-audit.py` | 把 `pkg/audit`（以及脱敏、留痕、注册表）的每一处修复退回一次，看对应的守卫**会不会变红** | 它变异的源码在底座（`pkg/audit`、`pkg/redact`、`pkg/reg`、`pkg/textx`）与两个服务仓（两个面的 handler）里，而**要证明会红的守卫有一部分在服务仓里**（答复守卫、留痕守卫）⇒ 一轮变异要同时动三个仓 ⇒ 三个仓共用的工具，只能有一份 |
| `mutate-version-guard.py` | 把「委派凭据必须有门禁」这条规则的每一处实现退回一次，看守卫**会不会变红** | 同上：词汇在底座、调用点在管理面、反门禁在执行面、守卫在服务仓 |
| `workset.py` | 多仓工作集的定义（哪些仓参与这一轮） | 两个变异脚本都要它 —— 抄一份会漂，而漂了的那份决定报告对着的是哪一份代码 |
| `review-prompt.md` | 独立审阅的提示词模板 | 三个仓共用同一份审阅模板；抄三份，漂了的那份就是最少有人看的那份 |
| `gen-idl.sh` | 从 `idl/jms/` 重新生成 `model/jms/` | 底座的共用词汇是生成物，生成它的脚本就该跟它住在一起 |
| `restore-go-modcache.sh` | 把 Go 的 module cache 补回来 | 离线环境的土办法（见脚本头的来历说明） |

## 多仓工作集

拆成三个仓之后，有几件事天生跨仓：审计留痕的守卫在服务仓、留痕的实现
在底座；委派凭据的门禁一边在管理面、一边在执行面。⇒ 这些脚本与守卫都需要
同一份「工作集」的定义。

约定的形状（**与守卫用的是同一套，别另造**）：

1. 环境变量 `JMS_SIBLING_ROOTS`（`:` 分隔的目录列表）；
2. 没有就用同级目录约定：`../jumpserver-mcp`、`../jumpserver-mcp-exec`。

用法：

    JMS_SIBLING_ROOTS=/path/to/jumpserver-mcp:/path/to/jumpserver-mcp-exec \
        python3 script/mutate-audit.py -v

## 变异脚本的自检（canary）

两个变异脚本都先跑一条 **canary**：先把守卫改坏，**证明它会红**，再开始扫。

⚠️ **canary 必须真的变红**。它没变红只有一个可能：变异压根没作用在被变异
的代码上（overlay 落在符号链接路径上就会这样）⇒ 后面每一条变异都会跑在
**未变异的代码**上 ⇒ 报告会说「守卫全是假的」，而真相是「它压根没扫到变异」。

⚠️ 两个脚本的**注入方式不一样，而且是有原因的，别互换**：

- `mutate-audit.py` 用 **overlay**：它变异的都是**被编译**的源码，而要证明
  会红的测试也是编译出来的 ⇒ overlay 够用，而且不用复制工作树。
- `mutate-version-guard.py` 用**整仓副本**：它要守的那条守卫**在运行时扫
  源码树**（`go/parser` 读 .go 文件自己判断）⇒ overlay 只影响编译器、
  看不见运行时的读盘 ⇒ 用 overlay 注入的源码树变异**根本不会落地**。
  ⇒ 它把**整个工作集**（三个仓）复制到 `/tmp` 里改、在副本里跑，
  **真仓一个字节都不碰**。

## 迁移状态

两个变异脚本都已迁到本仓，并按多仓工作集改造过。实测（三个仓并排、
`GOPROXY=off`）：

| 脚本 | canary | 变异 | 边界 | 备注 |
|---|---|---|---|---|
| `mutate-version-guard.py` | **变红 ✓** | 7/7 被测试杀掉 | 登记的那条仍绿 ✓ | 真仓逐字节未变 ✓ |
| `mutate-audit.py` | **变红 ✓** | 101/102 被测试杀掉 | — | 存活的那一条要由**服务仓**的守卫拦（见下） |

⚠️ **`mutate-audit.py` 存活的那一条是「守卫还没迁过来」，不是「守卫是假的」**：
它叫「词表长出自家参数名」，该由 `TestTheRepositorysOwnParametersAreNotMistakenForCredentials`
拦，而那条测试住在服务仓的 `internal/arch/` ⇒ 守卫没迁过来时，脚本找不到
它的声明处 ⇒ 报「测试没跑」⇒ 计入存活。**守卫迁过来之后重跑，它应当变红。**

⚠️ `mutate-version-guard.py` **依赖守卫已经迁到服务仓的 `internal/arch/`**
（脚本按「谁声明了 `TestADelegationCallSiteConsultsTheVersion`」找守卫，
不靠猜包路径）。守卫还没迁过来时，脚本会明确报「找不到守卫文件」而不是
假装跑过。
