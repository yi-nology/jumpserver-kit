# 独立审阅：怎么起、审什么

> 大改之后要有一双**没参与过**的眼睛。这份文件是那个「怎么起」的模板。
> 审阅结论要贴进汇报里 —— 没贴就等于没审。
>
> ⚠️ **它住在底座仓（jumpserver-mcp-kit）里，是因为三个仓共用这一份。**
> 独立审阅的模板抄三份，三份就会漂 —— 而漂了的那份是最少有人看的那份。
> 审哪一个仓，就把它指到那一个仓上（提示词里的 `<仓库路径>`）。

## 什么时候必须审

命中任意一条就要审：

| 触发条件 | 为什么是它 |
|---|---|
| 改动 **≥ 300 行**（`git diff --stat` 的合计） | 量到了，就有可能有没想清楚的地方 |
| 动了**协议**：请求体、字段名、路径、握手顺序 | 协议错了编译不报错，只在真机上报一个看不懂的错 |
| 动了**并发**：锁、goroutine、共享状态、连接池 | 并发错误**不自己暴露**，只在并发下才现形 |
| 动了**权限/身份**：谁能做什么、令牌、委派 | 这里的错是**静默扩权**或**静默收权** |
| 动了**失败路径**：超时、回退、重试、降级 | 顺利路径很少出错，**出错的都是不顺的那条** |
| 改了**存量行为**（不是纯新增） | 存量代码是被现网验证过的，动它要有第二双眼睛 |

各仓的 `./script/build.sh` 在改动够大时会提醒你这件事。

## 怎么起

用 `task` 起一个 `verifier` 子代理，提示词用下面这份模板（把 `<...>` 换掉）：

```
你正在审阅 <仓库路径>（<一句话说明这是什么仓>）里一处**未提交**的改动。

# 这次改动做了什么
<两三句：动机是什么、动了哪些层>

# 涉及的文件
新增：<路径列表>
修改：<路径列表>

# 你的任务
找出这次改动里的**具体缺陷**。重点按这个顺序：

1. **并发与加锁**（<涉及的文件>）：
   <把下面「已经在哪些地方栽过」里对应的条目挑出来，列成问题清单>
2. **失败路径**：超时、回退、重试、降级、错误分类。**顺利路径很少出错**，
   出错的都是不顺的那条 —— 请专门沿着「这里失败了会怎样」走一遍。
3. **契约面**：字段名、类型、必填/可选、错误码。**编译期发现不了的**。
4. **权限与身份**：这次的改动有没有让某个主体拿到它原来没有的权限？
5. **会破坏存量行为的改动**。

# 怎么工作
- 读代码；**不要相信注释** —— 本仓有几条注释写于实测之前，后来被实测推翻了。
  你的价值恰恰在于发现**代码与注释不一致**的地方。
- 可以跑 `GOPROXY=off go build ./...` 和 `GOPROXY=off go test ./...`
  （本机 module cache 在，不要跑 `go mod tidy`）。
- 探针程序只许写在 `/tmp` 下，**不许留在仓库里**，也不许改仓库里的任何文件。
  你是审阅，不是修复。
- 不要连真堡垒机，不要起 MCP 服务：这是静态审阅 + 本地构建/测试。

# 交付物
一份按严重度排序的发现清单。每条：
- file:line
- 具体错在哪
- **什么调用序列会踩到它**（具体的场景，不是「理论上可能」）
- 一两句的修法建议

没找到问题的类别，明确说「没找到」，不要凑数。
写清你跑过的命令。
```

## 已经在哪些地方栽过（审的人要重点看这里）

这份清单是**这几个仓的伤疤**。每一行都是一次真的返工 —— 拆仓之前它们在
同一个仓里，现在三个仓都还欠着这些教训。

### ① 超时不是超时，锁没法带截止时间等

- `sync.Mutex` **没有** `TryLock` 之外的「等一会儿就放弃」。`time.Mutex` 同样没有。
  → 改用 channel 实现的锁（`LockFor(d)`）。
- 超时之后 `sess.Close()` 之后 `<-waited` **无限等** → 传输卡死时，锁被一直占着，
  同一台机器上**其他会话自己的超时根本轮不到开始**。
- 教训：**任何「最多等 N 秒」的承诺，都要有能被中断的等待点**。

### ② 兜底会把真因吃掉

- 快速路径失败 → 回退慢路径 → 慢路径成功 → **看起来一切正常**，快速路径坏了没人知道。
- 症状：doctor 报 healthy，而快路径已经全挂。
- 教训：**兜底必须把「为什么兜底」带到答案里**（答复的 warning、doctor 的 WARN 行）。

### ③ 错误分类要把「资产问题」和「机制问题」分开

- 资产名写错、资产没账号 → 兜底也解决不了，白走十秒。
- 端点不存在、API 挂了、凭据被拒 → **这才是兜底该接的**。
- 教训：兜底条件要按**失败的原因**分，不是按「失败了」就兜底。

### ④ 成本/统计类的中位数不能混来源

- 把两种来源的样本混在一起取中位数 → 得到一个**两边都不属于**的数字。
- 而且还标着「实测」+ 样本数 0 → **错了还很自信**。
- 教训：样本要**带来源标签**，取中位数时按标签筛；没有就明说「没测过」。

### ⑤ 共享配置被并发写

- 一个 `*Config` 被 N 个 goroutine 同时写（每次写同样的值也是竞态）。
- 教训：共享结构要么**只读**（解析结果放带锁的 holder），要么**在构造时定好**。

### ⑥ 「失败」不等于「没发生」

- SSH：服务器**先回包再执行**。写失败 = 命令没发出去（可重试）；
  回包丢了 = 命令**可能已经在跑**（**永不重放**）。
- 教训：重试规则要按**投递状态**分，不是按「出错了」分。`rm -rf` 被跑两次的代价不对称。

### ⑦ 注释写于实测之前

- 本仓有过注释断言「池里的连接就是活着的堡垒机会话」—— 实测是**错的**
  （堡垒机记的是每条命令的 exec 会话；连接在会话列表里根本看不见）。
- 教训：**先量，再写注释**；注释里的每个事实性断言都该有测量支撑。

### ⑧ 脚本化补丁可能**根本没生效**

- `str.replace` 的模式没匹配上 → 代码保持原样，**但编译通过、测试也可能通过**。
- 当时是一个并发测试当场抓住的（「补丁没生效，测试当场抓住」）。
- 教训：改完行为要**验行为变了**，不是验编译过了。

### ⑨ 协议事实要实测，别抄

- 连接令牌的 `account` 要**账号 UUID**；填账号名/alias 会被拒。
  第三方仓说「v4 要 alias」—— 照抄会得出「koko 拒绝连接令牌」的错误结论。
- ⚠️ **后来把那条结论又翻过来了**：对着上游 v4.10.20-lts 源码读，
  v4 的 `get_asset_accounts_by_alias` 见到 UUID 就按 id 查，普通账号的 `Account.alias`
  本就等于它的 id ⇒ **UUID 在 v4 上也通**。第三方仓那句话只对**动态账号**成立。
- 教训：两份资料给出**相反**结论时，两份都可能是二手臆测 —— **连真机裁决**。
  ⚠️ 连真机都不行时（没有那个版本的部署），**去读那个版本的源码** ——
  源码是**一手**的，wiki 与第三方实现是**二手**的。
  ⚠️ 但源码级核对**不能写成「实测可用」**：本仓的 v4 支持就是这种状态
  （`docs/CONFIGURATION.md` §3.9 明写「源码级兼容，未实测」）。

### ⑩ 发布了 ≠ 指向新版本

- 发布脚本只复制二进制，**不改 MCP 配置**。于是「真调」调的是旧二进制。
- 症状看起来像「新代码坏了」，于是去改本来正确的代码。
- 教训：真调之前先确认 MCP 配置的 `command` 指向刚发布的那一版。

### ⑪ 两套实现会漂，而漂的方向是「**一个抹一个不抹**」

- 有过**两套**脱敏：留痕那份（底座仓的 `pkg/redact`）与管理面答复那份
  （管理面仓的 `biz/jumpserver/handler/redact.go`）。答复那份自己带一份词表 ⇒ 与留痕那份
  差 **14 条**（`passphrase`/`credential`/`cookie`/`kubeconfig`/`id_token`/
  `refresh_token`/…），而且**完全不认 JSON 形态** ⇒ `{"password":"x"}` 原样
  进 agent 的上下文窗口（实测 12/12 全漏）。
- ⚠️ 最难发现的形态是**同一个词在两种形态下结果不同**：`passphrase=x`
  （散文形态）明文，而 `{"passphrase":"x"}`（JSON 形态）被抹 ⇒ 读起来
  「这个工具在脱敏」，实际上有一半没脱。
- 教训：**要加词就加到那一份** —— 加第二条词表会让同一个词在两种形态下
  **一个抹一个不抹**。
- ⚠️ 收编时**形状不要一起收编**：留痕塌成 `****`（读者是看日志的人），
  答复保留键名与 scheme（读者是读命令记录的 agent，要看得见「跑了什么」）。
  ⇒ **词表共用，形状各走各的**。
- ⚠️ 底座（`pkg/`）里放**只被一个服务用的**函数 = 那个服务的私有代码穿着
  共用的名字 ⇒ 机械守卫按**包**（不是按符号）查这件事，且查的是**可达性**
  （执行面经 `pkg/reg` 间接用 `pkg/redact` ⇒ 直接 import 的读法会误报）。
  ⚠️ 拆仓之后这条更要紧：底座已经是**独立的仓**了，一份只在管理面用得上的
  函数待在底座仓里，就是另一个仓的私有代码穿着共用的名字。

### ⑫ 「有 `?`」与「有**同一个** `?`」是两件事

- 判「`&` 是分隔符还是凭据的一部分」靠「前面有没有 `?`」—— 但只看
  **整段文本里有没有** `?` 是不够的：前一句里的一个问号
  （`did it work? PASSWORD=AAA&bbb=1`）就替这条 `&` 开了口子 ⇒ 凭据尾巴
  明文进留痕。
- 教训：这类上下文判定必须问「**这个**标记是不是同一个里的」⇒ 判据是
  「**最近的** `?` 到匹配点之间没有空白/引号」；判不出来时往安全的一边。
- ⚠️ **递归必须把上下文带进去**：尾巴（`&` 后面那段）要再扫一遍，而那一遍
  必须用**同一份**上下文判断同一个 `&` ⇒ 否则两遍给出相反的答案 ⇒
  查询串的参数被吃掉（`?token=…&password=…&q=1` ⇒ `q=1` 消失）。

### ⑬ 变异扫描报的「假守卫」有三种，其中一种是**变异没生效**

- ① **守卫是假的**：行为变了，没有测试拦住。
- ② **变异是无效的**：行为**没变**（模式没匹配上、或改的方向让行为等价）
  ⇒ 测试当然绿着 ⇒ 报成「守卫是假的」而真相是「代码没动」。
- ③ **变异改了一处、报的却是另一处**：裸 `str.replace` 命中**多处** ⇒
  扰动了两条代码路径，却只报了一次检查 ⇒ **静默**失败（守卫跑了，跑在
  错的代码上）。
- 教训：**判据是「变异有没有真的改变行为」** ⇒ 把基线与变异版**同语料**
  差分（输出逐字节相同 ⇒ 变异无效）⇒ 方向反了要改的是**变异**，不是守卫。
- ⚠️ 变异的**方向**比模式更容易骗人：把判定改成 `&& false`（条件恒假）
  ⇒ 掩蔽照旧 ⇒ 行为没变。往「过掩」那一侧改才是有效的方向。
- ⚠️ 守测试必须挑**别的层处理不了**的形态，否则它守不住任何东西。
- ⚠️ 断言必须**逐个点名**每个秘密：断言只查 `"x"` 时，转义形态的值
  （`\"x\"`）根本不在其中 ⇒ 断言形同虚设。

### ⑭ 「匹配任何键再判断」有一个盲区：值里还藏着凭据

- 把规则从「只列凭据词」改成「匹配**任何** `key=value`，再问这个键像不像
  凭据」⇒ 键**不像**时若把整段（**连值**）原样放过 ⇒ 那段文本正则引擎
  再也不会看 ⇒ **值里的凭据活着**（「description=token=abc」）。
- 教训：键不是凭据时，**值要再扫一遍**（不是整段放过）⇒ 而「再扫一遍」
  只能调**那一条规则**（调整条流水线 ⇒ 无限递归）。
- ⚠️ 匹配括号要**跟踪字符串**：`{"note":"a}b"}` 里的 `}` 不是结尾 ⇒ 数到
  它就收尾 ⇒ 内层凭据留在明文**且文档被改坏**。
- ⚠️ 脱敏路径要**幂等**：标记被下一遍咬碎（"x-api-key = [REDACTED]" ⇒
  "x-api-key [REDACTED] [REDACTED]"）时，**读一遍看不出问题** ⇒ 症状是
  「同一段文本脱敏两次结果不同」。

### ⑮ 值形态不许跨字段：「一次匹配吃掉两个字段」

- 转义形态的值 `"(?:[^"\\]|\\.)*"` 里，`\\.` 能匹配下一个字段开头的
  `\"` ⇒ **一次匹配吞掉两个字段** ⇒ 而回调在「第一个键不是凭据词」时把
  整段**原样放过** ⇒ **第二个字段的凭据跟着逃了**。
- ⚠️ 真留痕里见过：`{\"username\":\"admin\",\"password\":\"…\"}` ⇒
  第一个键 `username` 不是凭据 ⇒ 整段放过 ⇒ `password` 的值明文进留痕。
- 教训：值形态里的转义**不许跨过下一个字段的开头**（`\\.` ⇒ `\\[^"]`）。
- ⚠️ ⚠️ **真调比单测更容易发现这类问题**：单元测试用的形态是人写的，
  而留痕里的是 **SDK 序列化之后**的形态（转义层数多一层）⇒ 写测试时
  要用**留痕里的真实字节**，不是「看起来像」的形态。

### ⑯ 「匹配任意键再判断」的键会**吃掉凭据前面的词**

- 把规则改成「匹配**任何** `key=value`，再问这个键像不像凭据」⇒ 匹配从
  **最左**开始 ⇒ `login failed: password: x` 的键成了 `login`、值成了
  `failed:` ⇒ **凭据自己拿不到一次匹配** ⇒ 它原样进上下文窗口。
- ⚠️ ⚠️ 这是**引入的回归**：旧版本（词表写在正则里）反而遮得住 ⇒ 只看
  「新旧哪个更严」会误判方向。
- 教训：键要由**共享词表**构造（模式从凭据开始），而不是「匹配后判断」。
  配套：**命令行参数与通用规则不能都抹**（否则两个标记、且不幂等）。

### ⑱ 「幂等」不覆盖「输出还是不是原来的东西」

- 一条**破坏性**的替换可以是幂等的：坏掉的形状**不再被规则命中** ⇒
  「洗两遍结果一样」照样成立 ⇒ 而输出已经不是那个文档了。
- ⚠️ 典型：转义的**层数**。Go 的**正则**里 `\\` 是一个字面反斜杠，而
  **替换串**里反斜杠**不做任何转义处理**（只有 `$name` 与 `$$`）⇒ 替换
  需要的字符数是模式的一半 ⇒ 用错了就把文档改坏（JSON 不再是 JSON）。
- 教训：断言要**同时**查「洗两遍一样」**和**「输出仍能解析」。

### ⑰ 守卫规则的「可达性」要算全图

- 机械守卫说「只被一个服务用的底座包 = 那个服务的私有代码」⇒ 若可达性只
  沿**底座内部**的边走 ⇒ 经 `internal/<服务>/…` 绕一跳的私有底座包**逃逸**
  （守卫全绿）。
- 教训：可达性走**全仓**的导入图（服务 → 自己的基础设施层 → 底座），
  只在最后一步统计**底座**包。

## 审完之后

- 发现**属实**的缺陷 → **当场修**，并把修法写进对应文件的注释（下次审的人会看那里）。
- 发现**不属实**的 → 在汇报里说明为什么不是问题，别默默跳过。
- 修完再跑一次 `./script/build.sh`（它编译并跑测试）。
  ⚠️ 并发相关的改动另外跑一次 `go test -race ./...` —— 构建脚本默认不race。
- **汇报里贴审阅的结论**：修了哪几条、哪几条判定为不属实、还有什么没查。
